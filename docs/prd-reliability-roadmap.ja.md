# TensorsLab Vision 信頼性の高い制作ワークフロー改修計画

[English](prd-reliability-roadmap.md) · [简体中文](prd-reliability-roadmap.zh-CN.md) · [한국어](prd-reliability-roadmap.ko.md)

## 製品の位置付け

TensorsLab Vision は、Agent 向けの画像・動画生成機能と、監査可能で再開可能なビジュアル制作ワークフローを提供します。agentao の承認の結び付け、明示的な状態、アトミックな永続化、リソース接続の考え方を参考にしますが、汎用 Agent ランタイム全体は導入しません。

## 優先順位

| 優先度 | 段階 | 解決する問題 | 成果物 |
| --- | --- | --- | --- |
| P0 | 承認と品質ゲート | 承認内容と実行内容のずれ、生成完了と納品可能状態の混同 | 内容ダイジェスト、素材ハッシュ、タスク単位の再承認、独立した QA・納品状態 |
| P0 | タスクの永続化と再開 | プロセス終了やポーリングのタイムアウトによる重複送信・重複課金 | `submit/status/wait/download`、タスク ID 保存、アトミックな状態記録 |
| P1 | 構造化結果 | Agent がログ文章から成功状態を推測する必要がある | 生成、照会、ダウンロード、QA 失敗を区別する統一 JSON |
| P1 | 上限付きバッチ実行 | SKU、複数比率、複数ショットを手作業で実行している | 同時実行上限、完了タスクのスキップ、再開可能な進捗 |
| P2 | 軽量 MCP 接続 | Agent ホストごとに能力の発見・呼び出し方法が異なる | 既存クライアントを再利用する MCP Tools / Resources |

## PR 1：承認ダイジェストと QA 状態

状態：実装済み、レビュー待ち。

承認時にタスクごとの SHA-256 ダイジェストを計算します。対象は、プロジェクト情報、変更禁止事項、プロンプト、ショット定義、生成設定、承認済み派発パラメータ、ローカル入力素材の内容ハッシュです。派発前に再計算し、承認後の変更があれば停止します。

一つのショットを修正した場合、そのタスクの承認だけを無効にします。生成、QA、納品状態は別々に記録します。商品事実、視覚品質、文字と権利、公開審査の四項目が `pass` または `not_applicable` になるまで、`delivery_status` は `ready` になりません。

## PR 2：タスク再開と構造化結果

実装予定：

1. 現在の簡易コマンドを維持しつつ、`submit`、`status`、`wait`、`download` を分離します。
2. 送信成功直後にタスク ID とリクエスト要約をアトミックに保存します。
3. 生成状態、ダウンロード状態、ファイル一覧、対処可能なエラーコードを統一 JSON で返します。
4. タスク ID があれば既存タスクの確認を再開し、ダウンロード失敗時はダウンロードだけを再試行します。
5. 送信結果が不明な場合は `submission_unknown` と記録します。サーバーが冪等キーに対応するまで、有料タスクを自動再送信しません。

受け入れ条件：終了したプロセスから同じタスクを再開できること、ポーリングのタイムアウトを生成失敗と扱わないこと、再ダウンロードで新しい生成タスクを作らないこと。

## PR 3：上限付きバッチ実行

任意の shell 文字列ではなく構造化された派発情報を読み取り、同時実行数とバッチ件数を制限します。タスク ID と進捗を自動記録し、送信済み・完了済み・QA 通過済みのタスクをスキップします。派発停止後もサーバーが受理したタスクを保持します。

受け入れ条件：再起動で重複送信しないこと、一件の失敗でバッチ全体の進捗を失わないこと、設定した同時実行数を超えないこと。

## PR 4：MCP Tools と Resources

初期 Tools はリクエスト確認、生成送信、タスク照会、結果ダウンロードを提供します。Resources はモデル能力、パラメータ説明、タスク記録、結果リンクを提供します。MCP 層は既存クライアントの検証とタスク保存を再利用し、別の生成実装を作りません。

リモート MCP Skills、OAuth、汎用 Durable フレームワーク、全画面 TUI、Codemode、汎用マルチ Agent 実行は今回の対象外です。有料生成の送信に自動再接続・再試行を適用しません。

## 成功指標

- 承認済みのプロンプト、パラメータ、制約、素材を変更すると派発が停止する。
- 一つのショット修正では、そのタスクの承認だけが無効になる。
- QA が未完了または失敗した成果物は納品・合成できない。
- プロセス終了後もタスク ID から同じタスクを再開できる。
- ダウンロード再試行で生成を再送信しない。
- バッチ実行で登録済みタスクを重複送信しない。
