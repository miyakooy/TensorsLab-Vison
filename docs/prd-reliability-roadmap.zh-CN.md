# TensorsLab Vision 可靠生产工作流改造计划

[English](prd-reliability-roadmap.md) · [日本語](prd-reliability-roadmap.ja.md) · [한국어](prd-reliability-roadmap.ko.md)

## 产品定位

TensorsLab Vision 是面向 Agent 的图像与视频生成能力，以及可审核、可恢复的视觉生产工作流。改造借鉴 agentao 在批准绑定、状态表达、原子持久化和资源接入方面的设计方法，但不引入通用 Agent 运行框架。

## 优先级

| 优先级 | 阶段 | 要解决的问题 | 交付结果 |
| --- | --- | --- | --- |
| P0 | 审批与质量门禁 | 批准内容与实际执行内容可能不一致；生成成功可能被误当成交付完成 | 内容指纹、素材哈希、任务级重新批准、独立 QA 与交付状态 |
| P0 | 任务持久化与恢复 | 进程退出或等待超时后可能重复提交并重复计费 | `submit/status/wait/download`、任务 ID 落盘、原子状态记录 |
| P1 | 结构化结果 | Agent 需要从日志文本猜测任务是否成功 | 统一 JSON 结果，区分生成、查询、下载和 QA 失败 |
| P1 | 有界批量执行 | SKU、多比例和镜头计划只能逐项手工执行 | 并发上限、跳过已完成任务、批次进度恢复 |
| P2 | 轻量 MCP 接入 | 现有能力难以被不同 Agent 宿主统一发现和调用 | 复用客户端的 MCP Tools 与 Resources |

## PR 1：审批摘要与 QA 状态

状态：已实现，等待评审。

批准时为每个任务计算 SHA-256 摘要。摘要覆盖：

- 项目、场景、平台、素材角色和不可变商品事实；
- 任务提示词、镜头定义及生成设置；
- 模型、尺寸、比例和时长等获批派发参数；
- 本地输入素材的内容 SHA-256，而不只是文件路径。

派发前重新计算摘要。提示词、参数、约束或素材内容发生变化时，派发停止并要求重新批准。修订单个镜头只撤销该任务的批准，其他任务继续保留原批准与输出历史。

任务状态拆分为：

- `generation_status`：生成是否完成；
- `qa_status`：四项检查是否完整通过；
- `delivery_status`：是否允许进入交付或视频合成；
- 兼容状态 `status`：供现有恢复和重试流程选择任务。

四项 QA 为商品事实、视觉质量、文字与权利、发布审核。每项必须是 `pass` 或明确的 `not_applicable`，任务才能成为 `delivery_status=ready`。

## PR 2：任务恢复与结构化结果

计划内容：

1. 将当前一体式客户端拆出 `submit`、`status`、`wait` 和 `download` 操作，同时保留现有快捷用法。
2. API 返回任务 ID 后立即原子写入本地任务记录，再进入轮询。
3. 输出统一 JSON，分别表达生成状态、下载状态、文件清单和可操作错误码。
4. 有任务 ID时只恢复查询；下载失败只重试下载。
5. 提交结果未知时记录 `submission_unknown`，在服务端支持幂等键之前不自动重提付费任务。

验收条件：进程退出后继续等待原任务；等待超时不等于生成失败；重新下载不调用生成接口。

## PR 3：有界批量执行器

计划内容：

- 读取结构化派发对象，不执行任意 shell 文本；
- 限制并发数和单批提交量；
- 自动登记任务 ID、进度、输出与失败阶段；
- 跳过已提交、已完成或已通过 QA 的任务；
- 停止派发时保留服务端已接受的任务，后续通过任务 ID 恢复。

验收条件：重启不会重复提交；单项失败不丢失整批进度；并发始终不超过配置值。

## PR 4：MCP Tools 与 Resources

首期 Tools 提供请求预览、提交生成、查询任务和下载结果。Resources 提供模型能力、参数说明、任务记录和结果链接。MCP 层必须复用现有客户端校验与任务存储，不能形成第二套生成实现。

远程 MCP Skills、OAuth、通用 Durable 框架、全屏 TUI、Codemode 和通用多 Agent 调度不进入本轮改造。付费生成提交不能直接采用断线自动重试。

## 成功指标

- 修改获批提示词、参数或素材后，派发会被阻止；
- 单镜头修订只撤销该任务的批准；
- QA 不完整或失败的结果不能进入交付和合成；
- 进程退出后能根据任务 ID 恢复同一任务；
- 下载重试不会再次生成；
- 批量执行不会重复提交已经登记的任务。
