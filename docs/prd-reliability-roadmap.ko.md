# TensorsLab Vision 신뢰성 중심 제작 워크플로 개선 계획

[English](prd-reliability-roadmap.md) · [简体中文](prd-reliability-roadmap.zh-CN.md) · [日本語](prd-reliability-roadmap.ja.md)

## 제품 포지셔닝

TensorsLab Vision은 Agent용 이미지·비디오 생성 기능과 감사 및 재개가 가능한 시각 제작 워크플로를 제공합니다. agentao의 승인 연결, 명시적 상태, 원자적 저장, 리소스 연결 방식을 참고하지만 범용 Agent 런타임 전체를 도입하지는 않습니다.

## PR 1: 승인 다이제스트와 QA 상태

상태: 구현 완료, 검토 대기.

승인 시 작업별 SHA-256 다이제스트를 계산합니다. 프로젝트 정보, 변경 불가 사실, 프롬프트, 샷 정의, 생성 설정, 승인된 실행 파라미터, 로컬 입력 자산의 내용 해시가 포함됩니다. 실행 명령을 만들기 전에 다시 계산하며 승인 이후 변경이 있으면 중단합니다.

한 샷을 수정하면 해당 작업의 승인만 취소됩니다. 생성, QA, 납품 상태는 별도로 기록합니다. 제품 사실, 시각 품질, 문구와 권리, 게시 검토의 네 항목이 모두 `pass` 또는 `not_applicable`이어야 `delivery_status`가 `ready`가 됩니다.

## PR 2: 작업 복구와 구조화 결과

상태: 구현 완료, 검토 대기.

1. 현재 간편 명령을 유지하면서 `submit`, `status`, `wait`, `download`를 분리합니다.
2. 제출 성공 직후 작업 ID와 요청 요약을 원자적으로 저장합니다.
3. 생성 상태, 다운로드 상태, 파일 목록, 조치 가능한 오류 코드를 통합 JSON으로 반환합니다.
4. 작업 ID가 있으면 기존 작업 조회를 재개하고, 다운로드 실패 시 다운로드만 다시 시도합니다.
5. 제출 결과가 불확실하면 `submission_unknown`으로 기록합니다. 서버가 멱등성 키를 지원하기 전에는 유료 작업을 자동으로 다시 제출하지 않습니다.

검증됨: 종료된 프로세스에서 동일 작업을 재개할 수 있고, 폴링 시간 초과와 생성 실패를 별도로 기록하며, 다운로드 재시도는 새 생성 작업을 만들지 않습니다. 워크숍 실행 명령은 실행 디렉터리에 작업 기록을 저장하고 `record_result.py`는 종료 상태 기록을 직접 가져올 수 있습니다.

## PR 3: 제한된 일괄 실행기

임의의 shell 문자열 대신 구조화된 실행 객체를 사용하고 동시 실행 수와 배치 크기를 제한합니다. 작업 ID와 진행 상태를 자동 기록하고 제출·완료·QA 통과 작업을 건너뜁니다. 새 작업 실행을 멈춘 뒤에도 서버가 접수한 작업은 보존합니다.

인수 조건: 재시작 시 중복 제출하지 않고, 한 작업의 실패로 전체 배치 진행 상태를 잃지 않으며, 설정한 동시 실행 제한을 넘지 않아야 합니다.

## PR 4: MCP Tools 및 Resources

초기 Tools는 요청 미리보기, 생성 제출, 작업 조회, 결과 다운로드를 제공합니다. Resources는 모델 기능, 파라미터 설명, 작업 기록, 결과 링크를 제공합니다. MCP 계층은 기존 클라이언트의 검증과 작업 저장소를 재사용하며 별도 생성 구현을 만들지 않습니다.

원격 MCP Skills, OAuth, 범용 Durable 프레임워크, 전체 화면 TUI, Codemode, 범용 멀티 Agent 실행은 이번 범위에 포함하지 않습니다. 유료 생성 제출에는 자동 재연결·재시도를 적용하지 않습니다.

## 성공 지표

- 승인된 프롬프트, 파라미터, 제약 또는 자산을 변경하면 실행이 차단된다.
- 한 샷 수정 시 해당 작업의 승인만 취소된다.
- QA가 미완료이거나 실패한 결과는 납품 또는 합성할 수 없다.
- 프로세스 종료 후 작업 ID로 동일 작업을 재개할 수 있다.
- 다운로드 재시도로 생성 요청을 다시 제출하지 않는다.
- 일괄 실행이 등록된 작업을 중복 제출하지 않는다.
